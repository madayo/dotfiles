# 基本

- 共通ルールは以下を参照。
@~/dotfiles/AI_RULES.md
- Codex 関連のファイル（`~/.codex/`、dotfiles の `codex/` と `.codex/`）は読まない・編集しない。Codex 側は Codex がレビュー・編集する。
- ユーザが `test` と入力した場合には `[~/.claude/CLAUDE.md is loaded.]` を出力する

# スキル

指示に応じて、対応するコマンドを選んで実行する。選んだコマンドと理由を一言伝えてから実行する。ユーザーがコマンドを直接指定した場合は、それに従う。「〜できるか？」のような質問には、コマンドを使わず回答だけを返す。

| 依頼 | コマンド |
| --- | --- |
| 原因・既存動作・変更影響の調査 | `/my-investigate` |
| 変更方針の設計・比較 | `/my-design` |
| 実装・修正と検証・セルフレビュー | `/my-implement` |
| 変更のレビュー構成の提案・承認後の実行 | `/my-review` |

## 推奨する使い方

必要な工程だけ使う。すべてを順番に呼ぶ必要はない。

| 状況 | 使い方 |
| --- | --- |
| 現状の仕様や動作を知りたい | 調査のみ |
| 原因不明の不具合 | 調査 → 設計 → 実装 → レビュー |
| 原因が明確な局所修正 | 実装 → レビュー（方針が未承認なら実装の中で提案・承認） |
| 要件が明確な機能追加 | 設計 → 実装 → レビュー |
| 既存構造が不明な機能追加・リファクタリング | 調査 → 設計 → 実装 → レビュー |
| 認可・決済・DB 変更など影響が大きい変更 | 設計 → 実装 → 重点レビュー（必要なら先に調査） |
| 文言・コメントだけの変更 | コマンド不要。レビューは必要に応じて提案 |

# 作業ルール

- 3ステップ以上のタスクは必ず Plan モードで開始する（承認済みの方針を実装する場合と、調査のみのタスクを除く）
- コマンドを使わない実装でも、実装後のセルフレビュー（サブエージェントで実施）は、`/my-implement` の「セルフレビュー」の手順に従う
