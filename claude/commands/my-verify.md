worktree モードで保留した検証を、メインツリーに戻って実行する。

依頼内容: `$ARGUMENTS`（空なら会話の文脈から判断し、判断できなければ質問する）

`/my-implement-wt` が残した検証待ちメモを使い、メインツリーで対象ブランチに切り替えて、docker で保留した検証を行う。承認済みの変更の検証なので、Plan モードには入らない。Plan モード中なら、plan ファイルに検証の要約を書き、ExitPlanMode を検証へ移るためだけに使う（新しい承認とは扱わない）。ExitPlanMode が拒否されたら、検証せず指示を待つ。

このセッションが worktree に入っている間（手順 2 で戻るまで）は、複数の git 呼び出しや、`$(git ...)` で別の git の出力を埋め込む形のコマンドが拒否される。git コマンドは 1 つずつ単純な形式で実行し、パスは先に単独のコマンドで取得して、その値を以降のコマンドに直接書く。メインツリーに戻れば、この制約はなく、メモの更新や削除も通常のツールでできる。メモ由来のパスやブランチ名は、コマンドに渡すときにクォートする。

## 手順

1. 対象ブランチを特定する。会話の文脈（直前の `/my-implement-wt` の報告）から判断し、なければ、`git rev-parse --path-format=absolute --git-common-dir` を単独のコマンドで実行して得たパスの下の `claude-verify/` を、`find <そのパス>/claude-verify -type f -name '*.md'` で再帰的に探す（ブランチ名の `/` はディレクトリになる）。ブランチ名は、メモの先頭行 `ブランチ: <名前>` を使う。複数あれば質問する。文脈もメモもなければ、検証を保留した作業がないので、質問して止まる。特定できたら、対象ブランチと、これから行う操作（worktree の取り外し、ブランチの切り替え）を一言示してから進める。
2. 現在地を判定する（`git rev-parse --path-format=absolute --git-dir` と `--git-common-dir` を、それぞれ単独のコマンドで実行し、一致すればメインツリー）。
   * worktree 内: `git status --short` で未コミット・未追跡の変更がないことを確認する（あれば止まって報告する）。問題なければ `ExitWorktree` を `action: "keep"` で呼び、あらためて現在地を判定する。メインツリーに戻れていなければ（このセッションで `EnterWorktree` していない場合など）、メインツリーで新しいセッションを開いて `/my-verify` を実行するよう案内して止まる。`remove` は worktree とブランチを消すので使わない。
   * メインツリー: そのまま次へ進む。
3. メインツリーの状態を確認する。
   * `git branch --show-current`（detached HEAD なら短縮 ID）で現在のブランチを控える。報告で、切り替え前のブランチとして示す。detached HEAD で、`git for-each-ref --contains HEAD refs/heads refs/remotes` の出力が空（どのブランチにも含まれない commit がある）なら、止まって確認する。
   * 現在のブランチがすでに対象ブランチなら、再実行か中断からの再開なので、手順 4・5 を飛ばして手順 6 へ進む。ただし、`git status --short` で変更一覧を確認し、前回の報告やメモに記録された検証中の修正と一致する場合だけ、止まらずに進む。一致しない、または特定できない変更があれば、止まって確認する（ユーザーが編集した変更を、前回の検証によるものとして扱わない）。切り替え前のブランチは、前回の報告を参照し、分からなければ「不明（再開のため）」と報告する。
   * それ以外は、`git status --short` が空であることを確認する。変更があれば、止まって報告する。
4. 対象ブランチを持つ別の worktree があれば外す。`git worktree list --porcelain` の先頭のエントリはメインツリーなので除き、2 件目以降から探す。
   * 外してよいのは、メモ（なければ直前の報告）に書かれたパスで、かつ `.claude/worktrees/` 配下のものだけ。それ以外が見つかったら、止まって質問する。
   * 外す前に `git -C <パス> status --short --ignored` を実行する。出力があれば（ignore 済みのファイルは、`--force` なしでも消える）、一覧を示して確認を取る。
   * `git worktree remove <パス>` で外す。`--force` は使わない。失敗したら止まって報告する。
5. 現在のブランチが対象ブランチでなければ、`git checkout --no-overwrite-ignore <ブランチ>` で切り替える。メインツリーの ignore 済みファイルとの衝突などで失敗したら、強制せず止まって確認する。
6. 検証する。メモ（なければ直前の報告）を読み、再インストールの要否は、メモの「依存の変更の有無」だけで判断しない。切り替え前のブランチとの lockfile の差分と、docker 側のインストール状態が対象ブランチの lockfile と一致しているかも確認し、依存の変更がある、または一致を確認できなければ、docker 側で再インストールする（実行先と副作用は、`my-implement.md` の手順 4 と同じく確認してから行い、lockfile が変わったら報告する）。その後は、`~/.claude/commands/my-implement.md` の手順 4〜6 を Read して、その手順に従う。
   * 修正が入った場合は、その差分に対して、同ファイルの「セルフレビュー」節に従う。
   * 承認された範囲外の修正が必要なら、変更せずに提案して止まる。
   * 修正は commit しない。
7. メモがあれば、後始末をする。すべて確認できたらメモを削除する。未確認が残る場合は、検証中に入れた未 commit の修正の一覧も書いて、メモを更新して残す。

## 報告

`~/.claude/commands/my-implement.md` の「報告」節と同じ形式で示す。切り替えたブランチ、切り替え前のブランチ、外した worktree、検証中に入れた未 commit の修正の一覧（なければ「なし」）も添える。
独立したレビューが必要なら、対象範囲を添えて `/my-review` を提案する。
