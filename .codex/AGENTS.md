# Codex 固有ルール

## 共通ルール

作業を始める前に `~/dotfiles/AI_RULES.md` を必ず読み、共通ルールとして適用する。
このパスは作業ディレクトリや `~/.codex/AGENTS.md` の配置場所に依存せず、dotfiles の実体を参照する。
読めない場合はその旨を伝え、共通ルールを確認するまで実装・外部への変更を進めない。

## 指示ファイルの境界

- 共通ルールとCodex向けの指示・スキルを作業指示として使う。
- 他エージェント向けの指示・スキル・コマンド（`CLAUDE.md`、`.claude/`、`claude/commands/`、`.copilot/` など）は作業指示として適用しない。
- 他エージェント向けのファイルは、ユーザーが参照を指定した場合のみ調査・比較資料として読む。その場合も作業指示として適用しない。

## スキルの選択

自動選択の対象は `my-investigate`・`my-design`・`my-implement`・`my-review` の4つ。
`my-pr`・`my-copilot-review`・`my-handoff` はユーザーがスキル名を明示した場合だけ使い、自動選択や後続工程への自動追加はしない。

- 日本語の依頼と会話の文脈から、目的・依頼範囲・完了条件を読み取り、対象4つの description に基づいて必要な組み合わせを選ぶ。この4つはユーザーによるスキル名の指定は不要。明示されたスキル・対象・制約は優先する。
- 行数やファイル数だけでなく、原因・仕様の不確実さ、設計判断の有無、影響範囲、互換性・権限・データへのリスクを見て選ぶ。小さくても重要な判断があれば設計を含め、方針が明確な局所修正では実装工程内の確認で済ませる。
- 必要なスキルだけ読み、その手順に従う。既に確認・承認済みの内容や、選んだスキル内で十分に扱える工程は重ねて実施しない。全工程の固定順や、別々のスキル呼び出しを必須にしない。スキル利用の効果が薄い単純作業は通常の対応で済ませる。
- 選択した工程が終わったら、結果と残る不確実さから次の工程を判断する。調査・設計だけの依頼はその成果を返して終え、修正・機能追加までの依頼は依頼範囲内で必要な工程を続ける。途中のスキルを再指定してもらう必要はない。
- 工程の選択自体を追加操作の許可と扱わない。承認の要否は共通ルールと各スキルに従う。
- 構成の指定をユーザーに求めず、複雑な依頼では選んだ構成と理由を短く伝える。質問は、要件や対象の不足が判断・実行に影響する場合に行う。

スキルは `~/.codex/skills/<スキル名>/SKILL.md` に配置する。利用できない場合はその旨を伝え、`AI_RULES.md` の共通ルールに従う。
